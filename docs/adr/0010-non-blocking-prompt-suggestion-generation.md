# Prompt suggestion generation runs in the background

`@mrclrchtr/supi-prompt-suggestions` will run only in PI TUI mode, because ghost-text prompt suggestions have no presentation surface in print, JSON, or RPC modes. In TUI mode, it will start suggestion generation from `agent_end` without awaiting the model call, using its own `AbortController` and generation id to cancel or discard stale results. If a new `agent_end` fires while a previous generation is still in-flight, the extension aborts the previous call and starts fresh generation for the latest assistant response. If the model does not respond within the configured generation timeout, generation is cancelled and the status spinner is cleared. On other failures (network error, auth failure), the spinner is likewise cleared; failures are recorded through SuPi debug events rather than left as persistent footer status. Any manual editor change dismisses the current or pending prompt suggestion for that assistant response, so stale ghost text does not reappear after the user starts writing. Generation is skipped entirely when the last assistant message contains no text content blocks (e.g., pure tool-call responses) or did not complete with stop reason `stop`. Awaiting inside `agent_end` would keep PI's agent run non-idle until the advisory suggestion finishes; background generation preserves PI responsiveness, while an extension-owned status spinner makes the remaining work visible without reusing PI's main working indicator.
