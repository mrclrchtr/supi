# Changelog

## [11.5.0]

- **Breaking:** `code_refactor_plan` takes only `operation`, and each operation names its own scope: `rename_symbol: { target, newName }`, `code_action: { file, range, kind, title? }` for server refactors such as `refactor.extract` (a range whose start equals its end marks a cursor position), and `source_action: { file, kind, title? }` for whole-file actions such as `source.organizeImports`. Import cleanup and unused-code removal no longer need a symbol anchor. Extraction now works where the server returns exact edits (for example gopls, rust-analyzer, and jdtls); the preview shows the server's generated name, which `rename_symbol` can change afterwards. When several matching actions produce different edits, the result lists each action's kind and title to pass back as `title`. Migration: move `target` into `rename_symbol`, replace `update_imports` with `source_action` kind `source.organizeImports`, `delete_dead_code` with kind `source.removeUnused` or `source.removeUnusedImports`, and `extract_function`/`extract_variable` with `code_action` kind `refactor.extract` ([#583](https://github.com/mrclrchtr/supi/issues/583)).
- `code_health` operation support lists `code_action` and `source_action` with the `refactor*` and `source*` kinds each server advertises, instead of fixed import, dead-code, and extraction entries. Servers that advertise the empty kind or no kind list, such as rust-analyzer, are marked as possibly returning unlisted kinds.
- An explicit `code_health` refresh that runs while a crashed language server is being replaced no longer makes the replacement fail. Previously, the request waiting on that replacement got no server and the recovery was recorded as cancelled, even though the new server was running.
- C and C++ headers mapped to another language by `code-intelligence.fileAssociations` (for example `**/*.h` as `cpp`) now use the language server's own diagnostics when the server registers them for that language. Previously, these headers were matched against the default C language, so the server's diagnostics for C++ never applied to them, and C-only diagnostics could be requested for files opened as C++.
- `code_health` server details are shorter. Operations with the same limit are listed together, so the extraction explanation appears once instead of once per operation, and operations a server does not support show only "server unsupported". Previously, every server, including bash and html, repeated a long typescript-language-server explanation twice.
- Cancelling a structural request, or reaching its deadline, no longer restarts the structural Worker. Previously every cancellation waited for the hard-stop timeout and discarded cached parse trees, so the next AST request parsed again from scratch.
- AST results for large files are much faster: converting node positions re-split the whole file for every node, which made extraction slow down quadratically with file size. On an 8,000-line TypeScript file, call-site extraction dropped from about 10 s to 0.3 s, and outline and export extraction from several seconds to under 0.2 s, so these requests no longer hit their deadlines on large files.
- Export extraction for JavaScript and TypeScript is more accurate: `export default "foo"` is reported as a default export instead of `export * from "foo"`, every name in `export var a, b` is listed, and `export import X = Y.Z` is listed as an `alias` export.
- In files containing a carriage return that is not part of a CRLF line ending (for example inside a template literal), AST positions after that character are correct again. Previously later lines were shifted, so ranges were truncated and some valid `code_inspect` positions were rejected as beyond the end of the line.
- Call ranges for Java, Kotlin, and Ruby now cover only the called expression (such as `a.b` in `a.b(1)`), as in other languages, instead of the whole call with its arguments and block. A Kotlin call with a trailing lambda, such as `bar(1) { it }`, is now reported once instead of twice in call search and `code_graph` callees.

## [11.4.0]

- `code_orientation` with a directory focus no longer embeds an instruction file (such as `CLAUDE.md`) that the agent already read in full with `read` since the latest compaction. Reads with `offset` or `limit`, truncated reads, and failed reads do not count. In observed sessions, about a quarter of embedded instruction text repeated a file the agent had just read.
- A symbol query with no workspace-symbol match now explains that only files in projects the language server has loaded are searched, and points to an AST definition search with `code_find`, a `target.file` lookup, or an anchor. Previously it suggested retrying `code_resolve`, the tool that had just failed ([#576](https://github.com/mrclrchtr/supi/issues/576)).
- TypeScript and TSX files with import types that take type arguments, such as `import("typebox").Static<T>`, now parse completely. Previously, AST results (`code_find`, file outlines, callees) for directories containing such a file were marked incomplete, so an empty search could not confirm that a name does not exist.
- `code_orientation` with a directory focus again shows the focused package's declared entry points (such as `exports` and `main` paths) inline, and lists all direct files in one compact line instead of the first ten, unless `maxResults` is set. Sections moved to captured details are named in one note instead of a separate "Captured navigation" section.
- `code_graph` references and implementations with the TypeScript server now report an incomplete result, naming the unloaded projects, when another `tsconfig.json` that includes the target file (such as a `__tests__` project that includes `../src`) has no open file. Previously, matches from such projects were silently missing and the result looked complete. Top-level declarations that their module does not export stay complete, because no other project can reference them.
- With the TypeScript 6 or earlier server (tsserver), `code_graph` implementations in workspaces with several TypeScript projects are now reported as incomplete: tsserver searches implementations only in the target file's project. The note suggests references or TypeScript 7 instead of opening more files.
- `code_resolve` with a file target now reports a **file outline** instead of a "Target group": the result heading reads `# File outline of …`, structured output uses `kind: "file-outline"` and `unknownLevelCount`, and messages from `code_graph`, `code_orientation`, and `code_refactor_plan` explain that they need one declaration handle from the outline. Each declaration is classified as top-level, member (inside a class, interface, enum, namespace, or object literal), or local (inside a function or method body) instead of a single "nested" category.
- The `code_resolve` file outline now lists only a file's own top-level declarations and members, with members indented below their class or interface. Imported names, names in `export { … }` lists, `export … from` statements (including `export *`, so a barrel file no longer looks empty), and declarations inside function bodies are counted under "Not listed" with their line span and the call that retrieves them. Declaration kinds are shown in lower case regardless of their source, and decorated Python functions and methods no longer appear twice. Rows are shorter: evidence notes appear only for declarations the language server did not confirm. For a large TypeScript file the default view now shows its classes and functions instead of only imports, and the full outline uses about a third fewer tokens.

## [11.3.0]

- Added package-specific release notes for code navigation, diagnostics, and refactoring.
- Capped `code_graph` reference results distribute sites across files, with matching source-reading suggestions.
- Fixed transient navigation failures when parallel requests first access different files, while retaining freshness checks.
- Rename and code-action planning now coordinate concurrent first file accesses without blocking parallel reads or weakening edit freshness checks.
- Scoped symbol queries no longer become incomplete solely because generated results were excluded outside the requested scope; ambiguous or genuinely incomplete evidence still requires explicit selection.
- Symbol queries scoped to an explicitly selected generated file or directory no longer report a false "Symbol not found" before the server has loaded that scope.
- Semantic symbol search with the TypeScript 6 or earlier server (tsserver) no longer reports existing symbols as missing at session start when a root config file, such as a dotfile excluded by `tsconfig.json`, sorts first; `code_find` and symbol targets now find them without opening a file first, and report an incomplete search instead of "not found" when no project file could be loaded.
- Symbol targets no longer require choosing from a single candidate when the only gap is an automatically excluded generated copy, such as a `dist/*.d.ts` declaration; the target resolves and notes the excluded path. Route failures and coverage gaps still require explicit selection. `code_graph` shows the same target notes, and semantic `code_find` reports an exact count and a null `partialReason` for such results while still disclosing the excluded paths in `automaticPathExclusion`.
- When a language server exits during startup, `code_health` and the status overlay now show the server's own error output instead of a transport error such as `write EPIPE` ([#570](https://github.com/mrclrchtr/supi/issues/570)).
- The status inspector adds **Refresh health** (`h` or F6), which runs the same bounded recovery and diagnostic refresh as `code_health({ refresh: true })` and reports its outcome separately from diagnostic confirmation ([#371](https://github.com/mrclrchtr/supi/issues/371)). Expanded file details now use only that file's diagnostic evidence, and a clean summary requires every requested tracked file to be confirmed.
- Health output distinguishes files without a compatible configured language server from configured servers that fail to start, and keeps a startup failure's explanation on later requests without retrying the server. Ownership roots outside the workspace are shown as absolute paths.
- An exact-file `code_health` refresh no longer rejects healthy routes for files outside the workspace or in automatically excluded paths.
- `code_graph` relations stay complete when only the display cap hides rows, and source paths use one canonical form across all code tools.
- `code_graph` callees and calls no longer report type-only `import("...")` references as calls, and TypeScript import types inside generic call arguments now parse correctly.
- `code_refactor_plan` omits edits that would leave text unchanged; a refactor with no real changes, such as renaming a symbol to its current name, no longer produces an applicable plan.
