# Changelog

## [14.1.0]

- `code_graph` shows the source line of every reference and implementation site, so a result answers how a symbol is used without a follow-up `read` or `rg`. Sites are listed one row per source line under their file (``  - L120:25 — `const stashes = await git(["stash", "list", "--format=%gs"], cwd);` ``) instead of as bare positions (`L117:24, L120:25`). Structured output adds an optional `text` to each item of these relations, and the expanded transcript shows the same line. Lines are trimmed and shortened when long; a site whose file cannot be read keeps the position-only form. Callee rows are unchanged.
- The code tools accept a nested argument that a model sent as a JSON string, such as `target: "{\"symbol\":{…}}"` for `code_resolve`. Before, the call failed with `target: expected object, got string` and was retried; in a probe this happened on the first `code_resolve` call of every rename task. Only a string that parses to the object or array the schema declares is decoded; any other value still fails validation.
- The system-prompt guidelines for the code tools name the action that calls for a tool instead of a tool category. `code_graph`: before renaming, removing, or changing the signature of an exported symbol. `code_refactor_plan`: renaming a symbol across files. `code_resolve`: a search for the declaration of one identifier. The `code_find` guideline ("broad code-aware discovery") is removed, and the `code_graph` description adds that it is selected before changing or removing a symbol. In a probe of five runs per task, an agent that had only used `rg` now called `code_refactor_plan` for a rename (5 of 5) and `code_resolve` for a declaration (5 of 5).
- A new `code_graph` guideline covers several symbols: issue one `code_graph` call per symbol in the same turn instead of one text search for all of them. In a probe of five runs, an agent asked which files use three exported functions made three parallel `code_graph` calls in its first turn (5 of 5; 1 of 5 before). The guideline had no effect on a task that named the file to change; the agent read the file and used `rg` there (0 of 5).

## [14.0.0]

- The LSP footer moved to the right side of the footer path line and is shorter: `λ 3✓ 1⟳ ◫43` instead of `λ lsp • 3 ✓ • 1 ⟳ • 43 open files`. Route counts are colored by severity (`✓` success, `⟳` accent, `↻` and `⊘` warning, `✗` error). The file count covers files synchronized to a language server, not files open in an editor; it uses `◫`, the Nerd Font file-with-eye outline (U+F0DCB), or `f` depending on the footer `icons` setting, and ASCII mode writes `lsp 3ok`. When LSP startup fails, the footer shows `λ ✗ config` for a configuration error and `λ ✗ unavailable` otherwise, instead of disappearing. Pi's built-in footer and other custom footers now show the LSP status too, on their extension status line. The footer renders the last published runtime state instead of re-querying every route on each render, and a route whose server command is missing or fails to start shows up without waiting for another state change.
- Symbol queries on TypeScript workspaces with several projects no longer return a short candidate list as complete. The language server searches only projects it has loaded, and the first query stopped after loading one. A query for `toolDescription` could list 13 of 26 declarations, and a name declared in two projects could be selected automatically from the one that was loaded. Every project root (up to 96) is now loaded before a symbol result is reported complete; roots past that limit are reported as a coverage limit ([#615](https://github.com/mrclrchtr/supi/issues/615)). Loading starts in the background when the TypeScript server is ready and takes a few seconds once per session. A symbol query that arrives earlier waits for it. While it runs, the LSP footer counts the TypeScript route under `⟳` instead of `✓`, and `code_health` and the `/supi-ci-status` inspector show it as `loading projects`; structured `code_health` servers carry `loadingProjects: true`. The opened files (one per project root) count as tracked files in `code_health` from then on, also in sessions that never run a symbol query ([#618](https://github.com/mrclrchtr/supi/issues/618)).
- `code_graph` references on a native TypeScript workspace no longer miss a test project whose first file in directory order is one the project excludes, such as `__tests__/fixtures/server.mjs`. Project warm-up opened only that file, which does not keep the project loaded, so references to `limitWorkspaceSymbolWarmRoots` came back provider-limited with `packages/supi-lsp/__tests__/tsconfig.json` is not loaded, and symbol queries could miss names declared only in that project. Warm-up now opens the project's next file and records the skipped one as a `workspace-symbol.warm-probe` debug event with outcome `excluded`. A project that includes the queried file but has no file of its own, such as a `__tests__/tsconfig.json` without tests, is no longer reported as not loaded: there was no file to open, so the advice could not be followed ([#616](https://github.com/mrclrchtr/supi/issues/616)).
- Several `code_*` calls in one parallel block no longer fail with `No routed LSP client could complete …` when together they open more than 32 new files, for example long candidate lists. Up to 1,024 first opens may now wait per language server. If that limit is reached, the result names the cause (`LSP could not open <file> for references: LSP input admission queue is full.`) instead of reporting a missing route.
- Two new LSP debug events are kept in the session file: `document.open-failed` (warning) names the server, file, and reason when a language server could not open a file, and `workspace-symbol.warm-pass` (info) summarizes one project warm-up pass with root counts and duration. Before, a failed open left no trace, and the per-file warm-up probes were `debug` events that high-volume request timings pushed out of the buffer.
- LSP batch operations no longer record one `request.timing` debug event per completed request. A diagnostic refresh over every open document and a project warm-up pass now report their completed requests on their own event (`diagnostics.timing` `refresh-open`, `workspace-symbol.warm-pass`) as `requests`, keyed by method with `count`, `totalMs`, and `maxMs`. Before, one refresh over 46 open documents recorded 46 near-identical timings and filled most of the 100-event debug buffer. Failed, timed-out, and cancelled requests are still recorded individually ([#619](https://github.com/mrclrchtr/supi/issues/619)).
- A project warm-up pass records far fewer debug events. It publishes one `runtime.transition` for all files it opened instead of one per file, and records a `workspace-symbol.warm-probe` event only for a file that did not load its project (`open-failed`, `probe-unavailable`, `inferred`); loaded projects are counted in `workspace-symbol.warm-pass`. Before, one pass over 46 projects recorded about 90 such events. The LSP footer therefore updates its open-file count less often during the pass ([#619](https://github.com/mrclrchtr/supi/issues/619)).
- A TypeScript symbol result at the native server's limit of 256 rows is reported as provider-limited instead of complete, so a target is not selected automatically from a truncated list. The limit is not applied to typescript-language-server (tsserver), which returns every match. The native server sorts exact names first and cuts afterwards, so a cut answer whose last row has another name still holds every declaration of the queried name. Such a result selects the only declaration of that name, with a note that partial-name matches may be missing: `code_resolve` for `git` scoped to `packages/supi-extras/src` resolves `footer-git-status.ts:102` instead of listing six candidates. Otherwise, when the query already has a scope, the note points to an anchor target (file, line, character) instead of suggesting a scope. If no row of a cut answer lies in the scope, the `code_resolve` failure no longer appends the readiness next steps, whose `target.file` advice led back to the same query ([#617](https://github.com/mrclrchtr/supi/issues/617), [#622](https://github.com/mrclrchtr/supi/issues/622)).
- A candidate list that is incomplete (for example provider-limited) ends with `Choose one candidate handle.` instead of also suggesting to narrow with `scope` or `symbolKind`. The list's own note names the step that applies, and the generic advice could contradict it ([#617](https://github.com/mrclrchtr/supi/issues/617)).
- A semantic `code_find` result that may be incomplete now states why: `more may exist — provider-limited; <reason>`, the same wording `code_resolve` uses. Before, it showed only `provider-limited`. The separate line about results excluded by the automatic path policy is omitted in that case, because the reason already contains it.
- Several reasons for an incomplete symbol result are no longer joined as `.;`. A reason that ends a sentence is followed by a space.
- Directory `code_orientation` in managed child sessions (Agent Runs and Reviewer Sessions) no longer repeats an instruction file the session already has: one loaded into its system prompt, or one it read in full with `read`. After a compaction the files are delivered again. The parent session already behaved this way ([#612](https://github.com/mrclrchtr/supi/issues/612)).
- Directory `code_orientation` names the instruction files it does not repeat: `Instruction files already supplied in this session, not repeated: …`. Before, the missing `## Instructions` section could not be told apart from a discovery failure. The workspace-root file is not listed, because nearly every session already has it.
- The note about results excluded by the automatic path policy is shorter: it names at most two example paths, and a path is written once unless the observed and canonical forms differ. Structured output still lists every collected example.
- Symbol targets in `code_resolve`, `code_graph`, and `code_orientation` select the only case-sensitive exact-name match instead of listing partial-name matches as candidates. A query for `registerSettings` no longer returns `# Multiple targets match` because `registerLspSettings` also exists; the result carries a note naming the matches that were not selected. An exact-name match that only imports or re-exports the name, such as the `alias` symbol TypeScript 6 and earlier report for `export { foo } from "./foo"`, no longer counts as a second declaration. Several declarations of one name still list candidates, now without the partial-name matches, which a note names instead. Incomplete provider results list every match.

## [13.0.0]

- **Breaking:** every `code_*` evidence list in structured details now carries `completeness`: `complete`, `capped`, `partial`, or `unbounded`. Scripts can read it directly instead of inferring completeness from a null `totalCount`. `code_orientation` source lists and context definitions replace `collectedCount`/`omittedCount` with one `evidence` list. Expanded TUI sections report rows hidden by the 20-row view separately (for example `25 of 30; 5 omitted; 5 rows hidden in view`), instead of adding them to the evidence omission count. Structured TUI chrome from sessions saved before this change falls back to the markdown output on resume.
- `code_graph`, `code_resolve`, and `code_orientation` report ambiguous targets and symbol-kind mismatches the same way: a `# Multiple targets match` or ``# No target matched provider kind `X` `` heading, one handle-first row per candidate with its container (``- `handle` — **name** (`kind`) in `Container` at `file`:line:col``), and a closing recovery sentence. All three set `details.status` to `disambiguation`, so the TUI shows "Choose a target". Previously `code_graph` reported a kind mismatch as invalid input, and `code_orientation` reported both cases as completed. Structured output schemas are unchanged.
- Workspace Overview and workspace/directory `code_orientation` now list Maven projects from `pom.xml` (model versions 4.0.0 and 4.1.0) as `maven-project`, identified by `project.artifactId`, and show `modules`/`subprojects` aggregation as `maven-modules` memberships. Parent inheritance is never treated as membership. The POM is read statically: Maven is not run, and properties, parents, and profiles are not resolved. Interpolated, profile-scoped, out-of-root, and unmatched module paths are reported as limitations ([#534](https://github.com/mrclrchtr/supi/issues/534)).
- Workspace Overview and workspace/directory `code_orientation` now list CMake projects (`cmake-project`) from `CMakeLists.txt` files that contain exactly one top-level `project()` call with a literal name. Repeated calls, calls inside conditions, functions, or macros, and variable-based names are disclosed instead of guessed. Targets and `add_subdirectory()` are not reported, and CMake is never run ([#535](https://github.com/mrclrchtr/supi/issues/535)).
- `code_health` no longer reports a clean result when no source diagnostics were checked. With zero requested files it says `No source diagnostics checked (0 tracked files).` and suggests an exact-file `refresh: true` check or the project's own typecheck. A clean result now names the confirmed file count and scope, and a snapshot with removed files is reported as incomplete. Removed files also make the diagnostic observation `partial` instead of `completed`, with a limitation that names them and suggests another `refresh: true` run, so `kind: "completed"` never appears beside `coverage: "incomplete"` ([#602](https://github.com/mrclrchtr/supi/issues/602)). A tracked-file snapshot read without `refresh: true` notes that it reflects the last LSP synchronization and may miss edits made outside Pi. Structured output adds `diagnostics.coverage` (`unavailable`, `none`, `incomplete`, or `confirmed`), using the same classification as the `/supi-ci-status` inspector ([#465](https://github.com/mrclrchtr/supi/issues/465)).
- `code_health` now reports a deleted tracked file as `removed` regardless of when the deletion happened. Previously the removal was lost if a passive read or a server-requested background diagnostic refresh ran first, typically within about half a second, and the next `refresh: true` call reported a clean result. A passive call (without `refresh`) also shows the removal but keeps it, and the next `refresh: true` call reports it once. Recreated files are no longer reported as removed ([#606](https://github.com/mrclrchtr/supi/issues/606)).
- A passive `code_health` tracked-file snapshot (without `refresh: true`) no longer reports a file as `confirmed` after it changed on disk outside Pi, for example through bash, an editor, or git. The snapshot compares each file's disk metadata with its last diagnosed read; a changed file is `unconfirmed`, the observation is `partial`, and the limitation names the file and suggests `refresh: true`. Its earlier diagnostics stay listed as possibly stale. A refresh or any later semantic request re-reads the file and restores `confirmed`, without a document change when only the metadata changed. Structured evidence documents add an optional `reason: "disk-changed"`. Edits that affect other files through imports are still not detected passively ([#599](https://github.com/mrclrchtr/supi/issues/599)).
- The collapsed `code_health` line no longer emits an empty styled span after section counts, so `tui_render` `marked` output reads `[success][bold]3[/bold][/success]` without a trailing `[muted][/muted]`.
- Truncation wording is the same in markdown, candidate lists, graph summaries, and TUI headers. For example, provider-limited candidate searches now read `1 candidate; 1 collected omitted; more may exist — provider-limited; <reason>` instead of a separate "Search completeness is unknown" sentence.
- `code_orientation` snapshots and truncated `code_*` output files are now written to one private per-user directory, `$TMPDIR/supi-<uid>/`, instead of a new `supi-*` directory per call. Identical content reuses one file, so repeated Workspace Overviews of an unchanged workspace share one snapshot; captures no longer record the per-call collection deadline. SuPi never deletes these files; the OS temp purge does ([#597](https://github.com/mrclrchtr/supi/issues/597)).
- Symbol name anchors from document symbols are computed against the text synchronized to the language server instead of the file on disk, so `code_resolve` and file outlines no longer point at the wrong column after unsaved or concurrent edits ([#594](https://github.com/mrclrchtr/supi/issues/594)).
- `code_graph` no longer drops TUI sections and evidence lines when a provider-limited relation list also excluded invalid provider locations.
- Starting Code Intelligence is about 100 ms faster: the TypeScript compiler API is loaded only when a tsconfig question is asked.
- `code_*` tool schemas are shorter (repeated position and default descriptions removed), so every request sends less prompt text. Call shapes and validation are unchanged.

## [12.0.0]

- **Breaking:** `code_find` takes one `search` selector instead of flat `query`, `mode`, and `kind`: `search: { ast: { kind, query } }` or `search: { semantic: { query } }`. A semantic search can no longer carry an AST kind. `scope` is renamed to `scopes`, because it takes a list; `code_resolve` and `code_health` keep the single-path `scope`. Migration: `{ query, mode: "ast", kind, scope }` becomes `{ search: { ast: { kind, query } }, scopes }`.
- **Breaking:** `code_inspect` takes `anchor` instead of `point`, the same `{ file, line, character }` name the other `code_*` tools use. The result reports the inspected location as `anchor` too, so `inspect.anchor` can be passed straight to another tool's `target.anchor`.
- `code_inspect` no longer sends a stray `~optional` keyword in its `maxResults` schema.
- `code_inspect` shows at most the first 12 lines (1,200 characters) of the syntax node's text and names the line range to read for the rest. Previously an anchor on a blank line or leading whitespace selected the file's root node and printed the whole file. Codemode results still carry the full text.
- Codemode now lists the `code_*` tools under a `code` namespace heading, so scripts can find them with `describeNamespace("code")` or `searchTools(query, { namespace: "code" })`. `describeNamespace` also returns the recommended call order. Every `code_*` tool now declares audited `readOnlyHint`, `destructiveHint`, `idempotentHint`, and `openWorldHint` annotations, which permission extensions can read from `pi.getAllTools()`. Only `code_refactor_apply` is marked destructive. `code_orientation` is marked open-world because consented Gradle observation can reach the network ([#582](https://github.com/mrclrchtr/supi/issues/582)).
- `code_refactor_plan` now previews code actions that only run a server command, such as kotlin-lsp extract variable and organize imports. SuPi runs the one selected command, captures the edit the server pushes, refuses it so no file changes, and stores it as the plan; the plan shows where its edit came from. This also works with clangd tweaks such as "Extract subexpression to variable", which report an error after their edit is refused. When a command pushes no edit, the reason notes there may be nothing to change. Only refactor, organize-imports, and fix-all commands run ([#584](https://github.com/mrclrchtr/supi/issues/584)).
- **Breaking:** `code_refactor_plan` takes only `operation`, and each operation names its own scope: `rename_symbol: { target, newName }`, `code_action: { file, range, kind, title? }` for server refactors such as `refactor.extract` (a range whose start equals its end marks a cursor position; positions outside the file are rejected before the server is asked), and `source_action: { file, kind, title? }` for whole-file actions such as `source.organizeImports`. Files outside the routed language server's project root are refused before the server is asked. Import cleanup and unused-code removal no longer need a symbol anchor. Extraction now works where the server returns exact edits (for example gopls, rust-analyzer, and jdtls); the preview shows the server's generated name, which `rename_symbol` can change afterwards. When several matching actions produce different edits, the result lists each action's kind and title to pass back as `title`. Migration: move `target` into `rename_symbol`, replace `update_imports` with `source_action` kind `source.organizeImports`, `delete_dead_code` with kind `source.removeUnused` or `source.removeUnusedImports`, and `extract_function`/`extract_variable` with `code_action` kind `refactor.extract` ([#583](https://github.com/mrclrchtr/supi/issues/583)).
- Kotlin local variables and parameters can be targeted by anchor (for example for `rename_symbol` after an extraction) when kotlin-lsp lists no document symbol for them. Previously the structural fallback recognized only `identifier` name tokens, not Kotlin's `simple_identifier`, and reported "No symbol target resolved".
- `code_refactor_plan` previews combine several edits on one line into one before/after entry, such as `- total` / `+ sumDoubled`, instead of showing the fragments a server like kotlin-lsp returns (`sumD`, `ub`, `ed`). The stored plan and the reported edit counts are unchanged, and the shown edits never stop in the middle of such a line.
- When a refactor plan or apply fails because a file changed while it ran (for example a plan running in parallel with an apply), the error now ends with "Retry after concurrent edits finish."
- `code_health` operation support lists `code_action` and `source_action` with the `refactor*` and `source*` kinds each server advertises, instead of fixed import, dead-code, and extraction entries. Servers that advertise the empty kind or no kind list, such as rust-analyzer, are marked as possibly returning unlisted kinds.
- An explicit `code_health` refresh that runs while a crashed language server is being replaced no longer makes the replacement fail. Previously, the request waiting on that replacement got no server and the recovery was recorded as cancelled, even though the new server was running.
- C and C++ headers mapped to another language by `code-intelligence.fileAssociations` (for example `**/*.h` as `cpp`) now use the language server's own diagnostics when the server registers them for that language. Previously, these headers were matched against the default C language, so the server's diagnostics for C++ never applied to them, and C-only diagnostics could be requested for files opened as C++.
- `code_health` server details are shorter. Operations with the same limit are listed together, so the extraction explanation appears once instead of once per operation, and operations a server does not support show only "server unsupported". Previously, every server, including bash and html, repeated a long typescript-language-server explanation twice.
- Cancelling a structural request, or reaching its deadline, no longer restarts the structural Worker. Previously every cancellation waited for the hard-stop timeout and discarded cached parse trees, so the next AST request parsed again from scratch.
- AST results for large files are much faster: converting node positions re-split the whole file for every node, which made extraction slow down quadratically with file size. On an 8,000-line TypeScript file, call-site extraction dropped from about 10 s to 0.3 s, and outline and export extraction from several seconds to under 0.2 s, so these requests no longer hit their deadlines on large files.
- Export extraction for JavaScript and TypeScript is more accurate: `export default "foo"` is reported as a default export instead of `export * from "foo"`, every name in `export var a, b` is listed, and `export import X = Y.Z` is listed as an `alias` export.
- In files containing a carriage return that is not part of a CRLF line ending (for example inside a template literal), AST positions after that character are correct again. Previously later lines were shifted, so ranges were truncated and some valid `code_inspect` positions were rejected as beyond the end of the line.
- Call ranges for Java, Kotlin, and Ruby now cover only the called expression (such as `a.b` in `a.b(1)`), as in other languages, instead of the whole call with its arguments and block. A Kotlin call with a trailing lambda, such as `bar(1) { it }`, is now reported once instead of twice in call search and `code_graph` callees.

## [11.4.0]

- `code_orientation` with a directory focus no longer embeds an instruction file (such as `CLAUDE.md`) that the agent already read in full with `read` since the latest compaction. Reads with `offset` or `limit`, truncated reads, and failed reads do not count. In observed sessions, about a quarter of embedded instruction text repeated a file the agent had just read.
- A symbol query with no workspace-symbol match now explains that only files in projects the language server has loaded are searched, and points to an AST definition search with `code_find`, a `target.file` lookup, or an anchor. Previously it suggested retrying `code_resolve`, the tool that had just failed ([#576](https://github.com/mrclrchtr/supi/issues/576)).
- TypeScript and TSX files with import types that take type arguments, such as `import("typebox").Static<T>`, now parse completely. Previously, AST results (`code_find`, file outlines, callees) for directories containing such a file were marked incomplete, so an empty search could not confirm that a name does not exist.
- `code_orientation` with a directory focus again shows the focused package's declared entry points (such as `exports` and `main` paths) inline, and lists all direct files in one compact line instead of the first ten, unless `maxResults` is set. Sections moved to captured details are named in one note instead of a separate "Captured navigation" section.
- `code_graph` references and implementations with the TypeScript server now report an incomplete result, naming the unloaded projects, when another `tsconfig.json` that includes the target file (such as a `__tests__` project that includes `../src`) has no open file. Previously, matches from such projects were silently missing and the result looked complete. Top-level declarations that their module does not export stay complete, because no other project can reference them.
- With the TypeScript 6 or earlier server (tsserver), `code_graph` implementations in workspaces with several TypeScript projects are now reported as incomplete: tsserver searches implementations only in the target file's project. The note suggests references or TypeScript 7 instead of opening more files.
- `code_resolve` with a file target now reports a **file outline** instead of a "Target group": the result heading reads `# File outline of …`, structured output uses `kind: "file-outline"` and `unknownLevelCount`, and messages from `code_graph`, `code_orientation`, and `code_refactor_plan` explain that they need one declaration handle from the outline. Each declaration is classified as top-level, member (inside a class, interface, enum, namespace, or object literal), or local (inside a function or method body) instead of a single "nested" category.
- The `code_resolve` file outline now lists only a file's own top-level declarations and members, with members indented below their class or interface. Imported names, names in `export { … }` lists, `export … from` statements (including `export *`, so a barrel file no longer looks empty), and declarations inside function bodies are counted under "Not listed" with their line span and the call that retrieves them. Declaration kinds are shown in lower case regardless of their source, and decorated Python functions and methods no longer appear twice. Rows are shorter: evidence notes appear only for declarations the language server did not confirm. For a large TypeScript file the default view now shows its classes and functions instead of only imports, and the full outline uses about a third fewer tokens.

## [11.3.0]

- Added package-specific release notes for code navigation, diagnostics, and refactoring.
- Capped `code_graph` reference results distribute sites across files, with matching source-reading suggestions.
- Fixed transient navigation failures when parallel requests first access different files, while retaining freshness checks.
- Rename and code-action planning now coordinate concurrent first file accesses without blocking parallel reads or weakening edit freshness checks.
- Scoped symbol queries no longer become incomplete solely because generated results were excluded outside the requested scope; ambiguous or genuinely incomplete evidence still requires explicit selection.
- Symbol queries scoped to an explicitly selected generated file or directory no longer report a false "Symbol not found" before the server has loaded that scope.
- Semantic symbol search with the TypeScript 6 or earlier server (tsserver) no longer reports existing symbols as missing at session start when a root config file, such as a dotfile excluded by `tsconfig.json`, sorts first; `code_find` and symbol targets now find them without opening a file first, and report an incomplete search instead of "not found" when no project file could be loaded.
- Symbol targets no longer require choosing from a single candidate when the only gap is an automatically excluded generated copy, such as a `dist/*.d.ts` declaration; the target resolves and notes the excluded path. Route failures and coverage gaps still require explicit selection. `code_graph` shows the same target notes, and semantic `code_find` reports an exact count and a null `partialReason` for such results while still disclosing the excluded paths in `automaticPathExclusion`.
- When a language server exits during startup, `code_health` and the status overlay now show the server's own error output instead of a transport error such as `write EPIPE` ([#570](https://github.com/mrclrchtr/supi/issues/570)).
- The status inspector adds **Refresh health** (`h` or F6), which runs the same bounded recovery and diagnostic refresh as `code_health({ refresh: true })` and reports its outcome separately from diagnostic confirmation ([#371](https://github.com/mrclrchtr/supi/issues/371)). Expanded file details now use only that file's diagnostic evidence, and a clean summary requires every requested tracked file to be confirmed.
- Health output distinguishes files without a compatible configured language server from configured servers that fail to start, and keeps a startup failure's explanation on later requests without retrying the server. Ownership roots outside the workspace are shown as absolute paths.
- An exact-file `code_health` refresh no longer rejects healthy routes for files outside the workspace or in automatically excluded paths.
- `code_graph` relations stay complete when only the display cap hides rows, and source paths use one canonical form across all code tools.
- `code_graph` callees and calls no longer report type-only `import("...")` references as calls, and TypeScript import types inside generic call arguments now parse correctly.
- `code_refactor_plan` omits edits that would leave text unchanged; a refactor with no real changes, such as renaming a symbol to its current name, no longer produces an applicable plan.
