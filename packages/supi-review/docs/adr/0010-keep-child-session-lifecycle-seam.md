# Keep the child-session lifecycle seam split from runtime creation

`runWithLifecycle` and `runIsolatedChild` stay separate modules. `runWithLifecycle` is the injectable lifecycle state machine: it accepts an already-created `AgentSession` and owns event subscription, the cancellation/timeout race, abort grace when a provider abort hangs, deferred `agent_settled` settlement, prompt-rejection classification, idempotent cleanup, and Child Lifecycle Trace redaction. `runIsolatedChild` sits above it, creating and disposing the `AgentSessionRuntime`, loading the isolated Reviewer Extension Set, and building the `ChildRunOutcome`. The seam falls exactly on "accept dependencies, don't create them": the lifecycle module accepts a session, the runtime module creates one.

`runIsolatedChild` is the only production caller of `runWithLifecycle`, so a call-count heuristic reads the seam as hypothetical and suggests merging the two into one module. That is wrong here: `session-lifecycle.test.ts` drives `runWithLifecycle` in isolation with a fake `AgentSession` (plain stubs) across the concurrency and privacy paths — races, abort grace, activity redaction, fail-closed tool lookup — with no real runtime. The fake session is a genuine second adapter at the seam, and the seam is the test surface for state-machine behavior that is impractical to reach through a real `AgentSessionRuntime`. Merging would force those tests to mock `createAgentSessionRuntime`, `createAgentSession`, and `SessionManager`, reintroducing the coupling the seam removes, or to drop that coverage. The split is a deliberate internal test seam and must not be collapsed on caller count alone.
