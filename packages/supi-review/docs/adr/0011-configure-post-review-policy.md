# Configure the containing Agent's post-review policy

> **Status: Amended (2026-08-14).** All fixing policies now require an applicability gate before any edit, and `fix` applies a lighter gate than `verify-and-fix`.

Use one scoped `review.postReviewPolicy` setting for both interactive and agent-initiated completed reviews when the user has not given a direct Post-Review Disposition; its values are `ask`, `verify`, `verify-and-fix`, `fix`, and `report`, with `ask` as the default. Ask offers verification, verification followed by fixing, fixing all or selected findings, or reporting; Verify asks again after independently confirming or refuting findings, while both fixing policies act on all applicable findings, including findings from completed tasks in a partial batch. Before any fixing policy edits, the containing Agent rejects findings that are refuted by evidence, stale, duplicated, incompatible, or not applicable to the live checkout. `fix` applies this light applicability gate and then fixes; `verify-and-fix` performs full independent confirmation of every finding before fixing confirmed findings. This remains a prompt-level containing-Agent protocol outside the Review Engine: no findings trigger no extra command turn, `/supi-review` with `report` remains terminal, complete paged output must be read before action, conflicting or stale findings are re-verified against live code, and non-trivial fixes use an existing targeted check when available.
